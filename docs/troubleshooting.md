# Troubleshooting

## Symptom table

| Symptom | Likely cause | Fix |
|---|---|---|
| `Open refused` from `ncp-telnet` | ITS NCP TELNET service not accepting RFCs, wrong packs, or ITS not fully booted | Confirm ARPA51 booted, restore clean packs, verify TELSER links/service files |
| `ncp-ping 41` works but `ncp-telnet 41` refuses | IMP/NCP path works, but TELNET server/service layer is wrong | Check ITS monitor options and `SYSBIN;TELSER BIN` links generated by ITS build |
| Hosted `@L 41` prints only `TELNET to host 051` repeatedly | Browser MTY path reaches the PiDP launcher banner but does not reach the ITS greeting | Check the PiDP SIMH MTY listener, ARPA51 console, and stale browser helper processes first; diagnose historical `ncp-telnet` separately |
| ARPA51 boot stops at `SWITCH 0 IS UP` / `YOU ARE NOW IN DDT` | PiDP front-panel switch 0 is set and ITS intentionally enters BUGDDT | Add a SIMH `expect` for `YOU ARE NOW IN DDT.` that sends ALT/P, or lower switch 0 before boot |
| Multiple `pdp10-ka-ncp-pidp` processes are running | Startup cleanup missed the PiDP-specific NCP binary name | Kill stale KA10 ARPA51 processes before restart; the launcher regex must include `pdp10-ka-ncp-pidp` |
| DSKDMP gets `FNF` or `PKNMTD` during boot | Boot command was mistyped or raced | Use SIMH `expect`; do not type DSKDMP commands through an external script after startup |
| `set imp ncp` fails | Wrong KA10 simulator binary | Use the combined Lars NCP + PiDP front-panel simulator as `pdp10-ka-ncp-pidp` |
| Stock PiDP ITS starts instead of ARPA51 | Front-panel mapping or launcher binary selection is wrong | Check `/opt/pidp10/systems/selections` and `pdpcontrol.sh` |
| ARPA51 is reachable but front-panel LEDs are dark | NCP simulator was built without PiDP GPIO support | Rebuild Lars' KA10 with `PIDP10=1`, PiDP `utils/pinctrl`, and install as `pdp10-ka-ncp-pidp` |
| Pi IMP link not established | Tailscale/UDP endpoint mismatch or wrong port pair | Check both IMP configs and `ss -uanp` on both machines |
| `Unknown ITS PDP-10` banner | Generic ITS machine name | Optional cosmetic issue; set a proper ITS machine identity later |

## Important lesson

Do not debug this by comparing raw disk-pack checksums. Different ITS hosts have different packs. Diagnose by runtime behavior:

1. Does the IMP link exist?
2. Does NCP ping work?
3. Does hosted `@L 41` reach the PiDP SIMH MTY line and show the ITS greeting?
4. If historical NCP TELNET is being debugged separately, does it reach TELSER?
5. Does ITS identify the intended host number?
